① mattpocock/skills（Matt Pocock）

⭐ 約 29.8 萬｜main 最後 commit 2026-10-19 23:51（台北）

github.com/mattpocock/skills ↗

作者每天實際在用的「真工程師」skill 合集，主打小、可組合、可自己改。分 engineering（寫程式用）和 productivity（一般流程）兩大類。README 說明它想解決四個常見問題：AI 沒做你要的、太囉唆、程式跑不動、程式越寫越亂。

你現在用的：grill-me：讓 AI 不停追問你的計畫，直到每個設計分支都講清楚才開始做。現在 grill-me 本身只是去呼叫底層的 grilling skill。作者也說 grill-me 偏「非程式用途」，寫程式建議改用 grill-with-docs。

推薦再學：

  • grill-with-docs：grill-me 的寫程式版：一樣追問，但邊問邊幫你建 GLOSSARY.md（專案用語表）和 ADR（重大決策紀錄），之後 AI 講話更精準、命名更一致。每次要改功能前用。
    github.com/mattpocock/skills/blob/main/skills/engineering/grill-with-docs/SKILL.md ↗
  • tdd：測試先行（紅→綠→重構），一次只做一小段垂直功能。會先跟你確認「測試要放在哪個介面（seam）」才寫測試，避免測一堆內部細節。做新功能或修 bug 時用。
    github.com/mattpocock/skills/blob/main/skills/engineering/tdd/SKILL.md ↗
  • diagnosing-bugs：難 bug／效能問題的除錯紀律：先做出「一跑就重現這個 bug」的檢查方式 → 縮小範圍 → 提出假設 → 加 log → 修 → 補回歸測試。遇到「怎麼修都修不好」時用。
    github.com/mattpocock/skills/blob/main/skills/engineering/diagnosing-bugs/SKILL.md ↗
  • improve-codebase-architecture：掃整個專案，找出可以整理成「深模組」（介面小、功能多）的重構機會，用 HTML 報告列出來，再挑一個跟你一起拷問。作者建議每隔幾天跑一次。
    github.com/mattpocock/skills/blob/main/skills/engineering/improve-codebase-architecture/SKILL.md ↗
  • handoff：對話太長時，把目前進度壓成一份交接文件（會遮掉金鑰等敏感資訊），開新對話繼續做。
    github.com/mattpocock/skills/blob/main/skills/productivity/handoff/SKILL.md ↗

💡 Cursor 安裝：npx skills@latest add mattpocock/skills -a cursor，安裝時記得勾 setup-matt-pocock-skills，並在每個專案先跑一次 /setup-matt-pocock-skills（to-spec、to-tickets、code-review 等需要它）。不知道用哪個時可以問 /ask-matt。

② cursor/plugins 裡的 pstack（Lauren Tan / poteto）

⭐ cursor/plugins 約 1.3 萬｜main 最後 commit 2026-10-20 10:24（台北）

github.com/cursor/plugins/tree/main/pstack ↗

Cursor 官方 plugin 倉庫裡的一套嚴謹工程流程。核心理念是「想快先要深」：寫更少但品質更高的程式，讓你敢同時開多個 agent 平行做事。

你現在用的：/poteto-mode：主入口。它讀你的需求，從 23 個 playbook（bug 修正、新功能、重構、效能、開 PR…）挑一個，把步驟列成 todo，需要時自動呼叫其他 skill。第一次要先跑 /setup-pstack 選模型。按 option+enter（Windows 為 alt+enter）可變成整段對話都生效的 custom mode。

推薦再學：

  • /poteto-help：剛開始用、不知道該用哪個 skill 或 playbook 時，問它，它會給你一句可以直接貼上的 prompt。
    github.com/cursor/plugins/blob/main/pstack/skills/poteto-help/SKILL.md ↗
  • /in-your-own-words：動手前請 AI 用自己的話複述你的目標和問題，確認它真的懂。跟 grill-me 很搭（grill-me 是它問你，這個是它講給你聽）。
    github.com/cursor/plugins/blob/main/pstack/skills/in-your-own-words/SKILL.md ↗
  • /how：請它帶你走一遍某個子系統是怎麼運作的。接手陌生程式碼時用。
    github.com/cursor/plugins/blob/main/pstack/skills/how/SKILL.md ↗
  • /blast-radius：看起來很小的改動，問它「還可能弄壞哪裡」，而且要用實際跑程式來證明安全，不是空口說。上線前、改共用程式時用。
    github.com/cursor/plugins/blob/main/pstack/skills/blast-radius/SKILL.md ↗
  • /interrogate：拿你的 diff，讓不同模型試著把它弄壞，還加一個嚴格的程式品質角度。可當 code-reviewer 之外的第二道審查。
    github.com/cursor/plugins/blob/main/pstack/skills/interrogate/SKILL.md ↗

💡 pstack 也有自己的 /tdd，和 mattpocock 的 tdd 功能重疊，挑一個用就好。

③ QingYunA/answer-me-with-html

⭐ 約 4,000｜main 最後 commit 2026-10-20 15:40（台北）

github.com/QingYunA/answer-me-with-html ↗

只有一個 skill 的專案：遇到複雜問題時，AI 只寫一份短 Markdown 草稿，內建 CLI 再把它排成一頁有圖、有表的 HTML。README 的實測：AI 要寫的 token 約只有直接寫 HTML 的 1/8。支援繁體中文。

你現在用的：answer-me-with-html：問比較、架構、流程這類問題時，得到一頁好讀的網頁，而不是一大段文字。頁面存在 ~/.answer-me-with-html/pages/。

推薦再學：

  • Always-on 模式（作者推薦）：預設關閉。打開後，每個「結論、摘要、計畫、比較」都會順便產生 2–4 格的小頁面且不跳出打擾你。照 README 那段文字貼給 agent，它會寫進規則檔。
    github.com/QingYunA/answer-me-with-html#always-on-mode-recommended ↗
  • 在頁面上做決策（ask 元件）：例如問「規劃這次 cache 修改」，頁面會引用你檔案裡的真實程式碼，把待決定的事做成選項；你在頁面上勾選、留言，按 Reply 就把答案整理成一則訊息貼回給 AI。很適合搭配 grill-me 的釐清流程。
    github.com/QingYunA/answer-me-with-html#components ↗
  • Explainer 影片：說「做一支 3b1b 風格的影片解說 XX」，會產生可離線播放、有旁白、圖會逐步出現的播放頁。學新概念或跟別人解釋時用。
    github.com/QingYunA/answer-me-with-html/blob/main/docs/video.md ↗

💡 設定直接用說的，例如「stop opening the browser」，或跑 /answer-me-with-html config。

④ msitarzewski/agency-agents

⭐ 約 16.2 萬｜main 最後 commit 2026-10-20 00:47（台北）

github.com/msitarzewski/agency-agents ↗

一大套「AI 專家角色」合集，分工程、設計、測試、資安、產品、專案管理等部門，每個角色有自己的個性、流程和交付物。Cursor 安裝會把每個角色轉成 .cursor/rules/ 下的 .mdc 規則檔。

你現在用的：Code Reviewer：像導師一樣做 code review，只抓正確性、資安、可維護性、效能，不糾結排版風格。

推薦再學：

  • Minimal Change Engineer：只改你要求的部分，拒絕「順便」重構；寧可三行相似程式碼也不提早抽象化。避免修個 bug 變成大改版。
    github.com/msitarzewski/agency-agents/blob/main/engineering/engineering-minimal-change-engineer.md ↗
  • AI-Generated Code Security Auditor：專抓 AI 寫的程式常見資安問題：寫死的金鑰、壞掉的資料列權限（RLS）、prompt injection 入口，跑「掃描→修→再掃」並對應 CWE 編號。上線前用。
    github.com/msitarzewski/agency-agents/blob/main/security/security-ai-generated-code-auditor.md ↗
  • Reality Checker：預設答案是「NEEDS WORK」，要有充分證據才說可以上線。防止 AI 太快說「做好了」。
    github.com/msitarzewski/agency-agents/blob/main/testing/testing-reality-checker.md ↗
  • Codebase Onboarding Engineer：只讀程式碼、追執行路徑，用事實解釋陌生專案的結構，不亂猜。接手舊專案時用。
    github.com/msitarzewski/agency-agents/blob/main/engineering/engineering-codebase-onboarding-engineer.md ↗
  • Technical Writer：寫 README、API 文件、教學，重點是準確和讀者好懂。
    github.com/msitarzewski/agency-agents/blob/main/engineering/engineering-technical-writer.md ↗

💡 只裝需要的角色：./scripts/install.sh --tool cursor --agent "Minimal Change Engineer"（--agent 可用 slug、顯示名稱或檔名）。
